# Operating Rules — eBay / AutoDS Dropshipping Machine

> **CONSTITUTIONAL PRECEDENCE (merge note, 2026-06-15).** The sovereign rulebook is
> `CLAUDE.md` (machine constitution). Where this domain file and `CLAUDE.md` differ, `CLAUDE.md`
> wins. In particular, the **constitutional evidence-label set** is the one in `CLAUDE.md §0.4`
> — `[OBSERVED — source+date]`, `[INFERRED — basis]`, `[UNKNOWN]`, `[PUBLIC RESEARCH REQUIRED]`,
> `[ESTIMATE declared]`. The expanded label table in §3 below (FACT / VERIFIED FACT / ASSUMPTION /
> LIVE ACCESS REQUIRED / OWNER GO REQUIRED) is a proposed domain superset that the owner has
> **explicitly DECLINED to ratify (governance closeout decision, 2026-06-15)**: per `CLAUDE.md`
> AUTONOMIA §10 it remains **quarantined and inactive** unless the owner explicitly approves it
> later. The `CLAUDE.md §0.4` set is the **primary and only active** evidence-label set — use only
> §0.4 in live claims. The behavioural rules below (gates, stop rules, language) are consistent
> with the constitution and are in force.

## 1. Phase Discipline

The machine must always route work through:

```text
System → Data → Analysis → Strategy → Execution → Measurement → Learning → Scaling
```

## 2. Non-Negotiable Rules

1. No strategy without collected data and analysis.
2. No execution without explicit approval.
3. No live platform writes without explicit owner GO.
4. No scaling without measurement and validation.
5. No invented numbers, policies, fees, margins, sales volume, conversion rates, account health status, or supplier reliability.
6. eBay, AutoDS, supplier, payment, tax, shipping, and return-policy facts must be labeled `PUBLIC RESEARCH REQUIRED` until verified.
7. Missing owner account data must be labeled `USER INPUT NEEDED`.
8. Internal setup work is allowed.
9. External research requires owner approval.
10. Account login/access requires owner approval.
11. Publishing listings requires explicit owner GO.
12. AutoDS configuration changes require explicit owner GO.
13. Supplier orders or payments require explicit owner GO.

## 3. Evidence Labels

| Label | Use |
|---|---|
| FACT | Directly observed in approved internal data |
| VERIFIED FACT | Confirmed from approved reliable source or owner-provided record |
| ESTIMATE | Calculated or inferred from partial data; basis must be stated |
| ASSUMPTION | Temporary working assumption; cannot drive live execution |
| UNKNOWN | Missing or unavailable |
| USER INPUT NEEDED | Owner-specific account/business data missing |
| PUBLIC RESEARCH REQUIRED | Current external fact, policy, fee, supplier, or platform rule needs verification |
| LIVE ACCESS REQUIRED | Requires login or dashboard/account access |
| OWNER GO REQUIRED | Requires live external modification, publishing, payment, order, or configuration change |

## 4. Forbidden Actions Without Explicit GO

- Edit eBay listings.
- Publish eBay listings.
- Change eBay prices.
- Change eBay business policies.
- Change AutoDS settings.
- Add/remove AutoDS suppliers.
- Enable/disable AutoDS automation.
- Place supplier orders.
- Issue refunds.
- Change shipping/tracking settings.
- Modify payment, tax, or return settings.
- Contact customers or suppliers as the owner.
- Spend money.
- Connect accounts.

## 5. Allowed Internal Actions

- Create machine files.
- Create source plans.
- Create data maps.
- Create risk maps.
- Create KPI maps.
- Create SOP shells.
- Create measurement templates.
- Create learning logs.
- Create scaling gates.
- Classify missing data.
- Mark public research requirements.
- Prepare next actions.

## 6. Default Stop Rules

| Phase | Stop Before |
|---|---|
| System | Stop after foundation files and next actions |
| Data Source Discovery | Stop before collection |
| Data Collection | Stop before analysis |
| Analysis | Stop before strategy |
| Strategy | Stop before execution plan |
| Execution Planning | Stop before live actions |
| Measurement | Stop before scaling |
| Scaling | Stop before expansion unless validation + owner approval exist |
